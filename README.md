# Does Shape Remember Loading Order reproducibility package

Package version: `reproducibility-package-v1.0.3` (release candidate).

Repository: <https://github.com/Abdulla-QsQs/shape-loading-order-reproducibility>
Version tag: `v1.0.3` (not yet created).

This release candidate is the reproducibility package for the matched-pool,
quasi-static sphere study. It is intended to reproduce the manuscript tables,
quality checks, paired statistics, and representative ParaView fields without
including unrelated drafts, temporary renders, or private project material.

## Scope and locked study

- Twelve balanced direction pools, seeds `4101`–`4112`.
- Twelve events per pool; each pool is run under `fixed`, `random`, and
  `feedback` policies, for 36 completed runs.
- The computational model is updated-geometry, small-strain J2 plasticity with
  linear isotropic hardening. It is quasi-static and does not model impact
  dynamics, contact duration, fracture, fatigue life, or microscopic damage.
- The primary comparison is the paired feedback-minus-random final residual
  shape-anisotropy difference.

## Contents

- `src/`: the single-run mechanics, ensemble orchestration, and validation/
  analysis code.
- `config/` and `environment.yml`: the frozen study configuration and pinned
  Conda environment specification.
- `inputs/direction_pools/`: canonical CSV files for the twelve balanced pools;
  `pool_manifest.csv` records their SHA-256 hashes.
- `results/raw/`: complete run metadata, cycle metrics, solver diagnostics,
  load-pool records, the ensemble manifest, and the representative XDMF/HDF5
  fields for `pool4101_feedback` (logs are intentionally omitted).
- `results/processed/`: audited combined tables and the analysis report.
- `results/verification/`: the five completed two-cycle mesh benchmarks for
  resolutions 4–8.
- `literature/`: the APA 7 bibliography, BibTeX export, and the preserved Word
  managed-source XML. No copyrighted article PDFs are redistributed.
- `supplementary_material/`: beta-definition, provenance, run audit, selector
  diagnostics, verification mapping, mesh-metadata clarification, and a future
  sensitivity protocol. These files do not reconstruct the unavailable pilot sweep.
- `tests/`: invariant tests for pool balance, policy consumption, pairing, and
  analysis checks.
- `tools/`: release-integrity, manifest, and regenerated-output checks.
- `VERSION.txt`, `PACKAGE_MANIFEST.txt`, and `SHA256SUMS.txt`: package identity
  and integrity records.

## Software and solver record

The publication metadata record Python `3.9.23`, legacy FEniCS/DOLFIN
`2019.1.0`, NumPy `2.0.2`, and pandas `2.3.1` under WSL2. The pinned Conda
environment specification also includes SciPy `1.13.1`, Matplotlib `3.9.4`,
and MUMPS.
The nonlinear solve uses MUMPS as the direct linear solver.

## Reproduce or audit

From the repository root inside Linux or WSL2, create and activate the recorded
environment:

```bash
conda env create -f environment.yml
conda activate fenics_env
```

The environment must be active before calling the runner; the runner does not
refer to a personal Conda installation or alter the user's shell.

### Audit the packaged results

The default mode verifies the manifest and SHA-256 records, runs all 11
invariant tests, regenerates the seven processed analysis files from the
packaged raw results, and requires content agreement after normalizing
platform-specific line endings:

```bash
bash run_publication_study.sh audit
```

Audit products are written below `reproduction_output/audit/`, which is ignored
by Git and is not part of the frozen release.

### Run the full 36-member ensemble

To rerun the finite-element ensemble rather than audit the packaged outputs:

```bash
bash run_publication_study.sh full
```

Fresh results are written below `reproduction_output/full/`; the frozen
`results/` directory is never overwritten. On the publication machine, the 36
recorded solves represented approximately 4.25 sequential solver-hours in
total. Runtime is hardware dependent. An interrupted full reproduction may be
resumed: a member is skipped only when its metadata, policy seed,
configuration hash, and requested cycle count exactly match.

Pool directions are generated by `numpy.random.default_rng(pool_seed)`. Policy
seeds are `pool_seed*1000 + 11` for fixed, `+23` for random, and `+37` for
feedback. The primary bootstrap uses `numpy.random.default_rng(20260701)` with
20,000 resampled paired means and a percentile 95% interval. For the current
12-pool primary comparison, the two-sided sign-flip test enumerates all
`2^12 = 4096` sign assignments exactly; it is not a Monte Carlo approximation.

## Feedback-coefficient provenance

The publication coefficient is `beta = 250`, recorded in the frozen
configuration and every run metadata record. The protocol records that this
value was selected from design-stage pilot selection-entropy behaviour rather
than from a final mechanical outcome. A separate pilot calibration log or
entropy sweep was not present in the retained project records searched for
this release. The package therefore reproduces the final ensemble conditional
on the locked value `beta = 250`; it does not claim to redistribute a pilot
calibration artefact that is not available.

## Ablation status

The centroid-only selector ablation was not run. It would require an additional
policy arm and new matched simulations, so it was not silently mixed into the
locked 36-run ensemble. The selector–outcome overlap (both the feedback rule
and `A_g` use covariance tensor `Q`) remains an explicit unresolved limitation.
